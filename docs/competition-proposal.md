# AI活用コンペ提出書類 下書き

## 企画名

**gemini-hub: 自然文リクエストをAIで処理するタスク管理・業務自動化ハブ**

## 1. 企画概要

本企画では、SlackやiOS Draftsから送信された自然文のリクエストをAIで解析し、内容に応じてタスク登録・分類・保存・返信を行うWebシステムを開発しました。

現在の実装では、利用者がSlackやDraftsに「明日までに資料を確認する」「来週金曜に病院へ行く」のような自然な文章を送るだけで、Google Gemini APIが内容を解析し、タスク名・期限・カテゴリ・場所などの情報を構造化してPostgreSQLに保存します。保存されたタスクはWeb画面から確認でき、完了状態への変更も可能です。

本システムの本質は、単なるToDoアプリではなく、**外部から来たリクエストを受け取り、AIで意味を解釈し、処理結果をAPI・データベース・Slackなどへ返す「AIリクエスト処理ハブ」**である点です。

この構成を応用することで、現在のタスク管理だけでなく、社内問い合わせ対応、議事録からのタスク抽出、申請内容の自動整形、ナレッジ検索、外部API連携など、さまざまな業務自動化へ拡張できます。

## 2. 背景・課題

日常業務や個人作業では、タスクや依頼がSlack、メモアプリ、口頭、メールなど複数の場所に分散しがちです。また、ToDoアプリに登録する際には、タスク名・期限・分類・場所などを手入力する必要があり、入力の手間が原因で登録が後回しになることがあります。

その結果、次のような課題が発生します。

- タスクや依頼が複数ツールに分散する
- ToDo登録に手間がかかり、運用が継続しにくい
- 「明日」「来週金曜」などの自然な表現を手動で日付に変換する必要がある
- 会話やメモの中にある依頼事項が見落とされる
- 定型的な分類・登録・返信作業に時間がかかる

本企画では、普段利用しているSlackやDraftsから自然文のまま入力し、AIが必要な情報を抽出・整理することで、タスク管理や業務受付の負担を減らすことを目的としました。

## 3. 成果物

開発した成果物は、**AIを利用したタスク管理・リクエスト処理Webアプリケーション**です。

### 現在実装済みの主な機能

- Slackから自然文でタスクを投稿
- iOS DraftsからHTTP API経由でタスクを投稿
- Gemini APIによる自然文解析
- タスク名、期限、カテゴリ、場所の自動抽出
- PostgreSQLへのタスク保存
- Web画面でのタスク一覧表示
- タスクの完了操作
- Slackイベントの非同期処理
- AI解析失敗時のフォールバック保存
- 操作ログ・デバッグ画面による運用確認
- Docker ComposeとGitHub Actionsを利用した本番運用

### 現在の利用イメージ

```text
Slack / Drafts
  ↓
Laravel API
  ↓
Queue Job
  ↓
Gemini APIで自然文を解析
  ↓
構造化データへ変換
  ↓
PostgreSQLへ保存
  ↓
Web UI / Slack返信で結果を確認
```

## 4. 利用したAI

本システムでは、**Google Gemini API**を利用しています。

利用モデル:

- Gemini 2.5 Flash
- Gemini 2.5 Pro

主な利用用途は、自然文からアプリケーションで扱える構造化データを抽出する処理です。

### AI処理の例

入力:

```text
明日までに資料を確認する
```

AIによる抽出結果の例:

```json
{
  "title": "資料を確認する",
  "due_date": "2026-06-12",
  "category": "work",
  "location": null
}
```

「明日」「来週の金曜」「今月末」などの相対日付は、現在日時とタイムゾーンを基準に解釈します。一方で、本文に明示されていない情報はAIが推測で作らないようにし、不明な項目は `null` として扱う設計にしています。

このように、AIを単なる文章生成ではなく、**自然文を業務システムで処理可能なデータへ変換するための中核機能**として利用しています。

## 5. システム構成

本システムは以下の技術で構成されています。

| 領域 | 技術 |
| --- | --- |
| バックエンド | Laravel 11 |
| フロントエンド | React / Tailwind CSS / Vite |
| データベース | PostgreSQL 16 |
| AI | Google Gemini API |
| 外部連携 | Slack Events API / iOS Drafts HTTP API |
| 非同期処理 | Laravel Queue |
| インフラ | Docker Compose / nginx / Caddy |

Slackイベントは、Slack側のタイムアウトを避けるため、Laravelで受信後すぐに応答し、実際のAI解析・DB保存・Slack返信はキューで非同期実行します。

これにより、外部APIからのリクエストを安定して受け取り、処理内容に応じて後続アクションを実行できる構成になっています。

## 7. 工夫した点

### 7.1 AIを「構造化処理」に利用した点

本システムでは、AIを単なるチャット応答や文章生成ではなく、自然文を業務システムで扱いやすい構造化データに変換するために利用しています。

例えば「明日までに資料を確認」という文章から、タスク名と期限を抽出し、DBに保存できる形式へ変換します。これにより、利用者は入力形式を意識せず、普段の言葉でタスクを登録できます。

### 7.2 リクエスト処理ハブとして拡張しやすい構成

入力元はSlackやDraftsですが、処理の流れは汎用的です。

```text
リクエスト受信
  ↓
AIによる意味解析
  ↓
処理内容の決定
  ↓
DB保存 / 外部API連携 / 返信
```

この構成により、入力元や処理先を追加することで、タスク管理以外の用途にも展開できます。

### 7.3 非同期処理による安定性

Slack連携では、外部サービス側の応答時間制限があります。そのため、リクエスト受信後すぐに応答し、AI解析など時間がかかる処理はキューで実行しています。

これにより、AI APIの応答時間に左右されにくい安定した処理が可能になっています。

### 7.4 失敗時に入力内容を失わない設計

AI APIは一時的なエラーや混雑によって失敗する可能性があります。本システムでは、AI解析に失敗した場合でも元の入力をフォールバックとして保存し、タスク化できるようにしています。

これにより、AI連携を前提としながらも、実運用での信頼性を意識した設計にしています。

## 8. 拡張可能な使いみち

現在の実装はタスク管理に特化していますが、仕組みとしては「リクエストを受け取り、AIで処理し、結果を返す」基盤です。そのため、以下のような用途へ拡張できます。

### 8.1 社内問い合わせの一次受付AI

Slackやフォームから来た問い合わせをAIが分類し、担当部署や対応方法を自動で振り分ける用途です。

例:

- 「PCが起動しない」 -> 情シスカテゴリ
- 「経費精算の方法を知りたい」 -> 総務カテゴリ
- 「有給の申請方法を教えて」 -> 人事カテゴリ

想定フロー:

```text
問い合わせ投稿
  ↓
AIが内容・カテゴリ・緊急度を判定
  ↓
担当部署へ通知
  ↓
必要に応じて一次回答を返信
```

これにより、問い合わせ対応の初動を効率化できます。

### 8.2 議事録・会話メモからのタスク自動抽出

会議メモやSlackの会話ログから、担当者・期限・タスクをAIが抽出する用途です。

例:

```text
田中さんは来週金曜までに見積書を作成。
佐藤さんは顧客へ確認メールを送る。
```

抽出結果の例:

```json
[
  {
    "assignee": "田中",
    "title": "見積書を作成",
    "due_date": "2026-06-19"
  },
  {
    "assignee": "佐藤",
    "title": "顧客へ確認メールを送る",
    "due_date": null
  }
]
```

現在のタスク抽出機能を拡張するだけで、個人ToDoからチームタスク管理へ発展できます。

### 8.3 申請・依頼フォームの自動整形

自然文で送られた依頼を、社内申請に必要な形式へ自動変換する用途です。

例:

```text
来週の月曜に東京出張します。新幹線代と宿泊費を申請したいです。
```

抽出結果の例:

```json
{
  "type": "出張申請",
  "date": "2026-06-15",
  "destination": "東京",
  "expenses": ["新幹線代", "宿泊費"]
}
```

事務作業の入力負担を減らし、申請内容の抜け漏れ防止につながります。

### 8.4 メール・Slack内容の要約と返信案作成

長いメールやSlack投稿をAIが要約し、返信案を作成する用途です。

例:

- 長文メールを3行で要約
- 顧客からの問い合わせに対する返信案を作成
- Slack上の依頼内容を整理してタスク化
- クレーム文面から対応方針を提案

現在の入力・AI処理・返信の仕組みを利用すれば、文章処理ハブとして展開できます。

### 8.5 社内ナレッジ検索ボット

社内資料やFAQを参照し、質問に対して回答するAIボットとして利用する用途です。

例:

```text
交通費精算の締切はいつ？
```

回答例:

```text
毎月25日までです。申請は経費精算システムから行ってください。
```

将来的に文書DBや検索機能を追加することで、社内ナレッジ検索やFAQ対応へ拡張できます。

### 8.6 外部API連携による自動実行エージェント

AIが入力内容を解釈し、必要な外部APIを呼び出す用途です。

例:

```text
明日の10時に佐藤さんと打ち合わせを入れて
```

将来的な連携先:

- Google Calendarへの予定作成
- Slackへの通知
- タスク管理ツールへの登録
- メール下書きの作成
- 顧客管理システムへの記録

現在の構成に外部API連携を追加することで、自然文から業務アクションを実行するエージェントへ発展できます。

## 9. 期待される効果

本システムによって、タスク登録や依頼処理にかかる心理的・作業的負担を減らすことができます。

## 12. まとめ

gemini-hubは、SlackやDraftsから送られた自然文をGoogle Gemini APIで解析し、構造化されたタスクとして保存・管理するAI活用システムです。

現在は個人用ToDo管理を中心に実装していますが、設計としては、外部からのリクエストを受け取り、AIで意味を解釈し、処理結果をDBやAPI、Slackに返す汎用的なハブになっています。

そのため、今後は社内問い合わせ対応、議事録からのタスク抽出、申請内容の自動整形、社内ナレッジ検索、外部API連携による自動実行エージェントなど、さまざまな業務効率化に応用できます。

本企画は、AIを単なる文章生成ではなく、実際の業務フローに組み込むことで、入力・分類・登録・返信といった定型作業を効率化する実用的な取り組みです。
