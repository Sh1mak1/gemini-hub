## 完了した作業

### Gemini API 耐障害化（`e6394e9`）

**背景:** 夜間に 429 / 503 が多発し、Slack からタスクが登録されないことがあった。

1. **リトライ + モデルフォールバック**（`GeminiClient`）
   - 429 / 500 / 502 / 503 / 504 で指数バックオフ（デフォルト 2s → 4s → 8s、最大 3 回）
   - 失敗時にモデルチェーンへ切替: `gemini-2.5-flash` → `gemini-2.0-flash` → `gemini-2.0-flash-lite`
   - env: `GEMINI_MODEL_CHAIN`, `GEMINI_RETRY_ATTEMPTS`, `GEMINI_RETRY_BASE_DELAY_MS`

2. **フォールバック登録**（`fallback_tasks` テーブル）
   - AI 全滅時もタスクは必ず登録（`title` = 入力 1 行目、`raw_input` に全文）
   - `tasks`（AI 成功）と **テーブル分離**。フロント `/tasks` では両方をマージ表示
   - 完了 API: `PATCH /tasks/{source}/{id}/complete`（`source` = `ai` | `fallback`）
   - Slack 通知: `⚠️ タスクを登録しました（AI未解析）`

| ファイル | 説明 |
|----------|------|
| `fallback_tasks` migration | AI 未解析タスク用 |
| `TaskPersistenceService` | outcome → DB 保存 |
| `TaskListAssembler` | 一覧マージ・表示用フォーマット |
| `GeminiApiException` | ステータス・リトライ可否 |

### タイムゾーン修正（`b051f45`）

**背景:** 操作ログの日時・タスク開始日が UTC のまま表示され、JST とずれていた。

- `DisplayTime` ヘルパー追加（DB/ログは UTC、**表示は JST**）
- `APP_DISPLAY_TIMEZONE=Asia/Tokyo`（デフォルト）
- `LOG_OPERATIONS_LOG_TIMEZONE=UTC`（ログファイルの書き込み時刻の解釈）
- `OperationLogReader`: UTC → JST 変換、日付フィルタも JST 基準
- `TaskListAssembler`: `created_at` を JST で `start_date` に反映

## 追加セッション — Slack #Kyou 本日期限タスク投稿

### 背景

`#Kyou` チャンネルに、**毎朝 9 時（JST）** 本日が期限の未完了タスク一覧を投稿し、タスクに変更があったら **再投稿** する機能を実装・本番反映。

### 実装（コミット）

| コミット | 内容 |
|----------|------|
| `5121678` | `TodayDueTasksSlackService` / `slack:post-today-tasks` / スケジューラ（9:00 JST） |
| `a89f876` | 投稿前の `conversations.join`（スコープなし時は手動招待が必要） |
| `fef3320` | Kyou 同期を通知より先に実行。通知失敗を catch してタスク登録は継続 |
| `1146938` | `chat.update` やめ → **旧メッセージ削除 + 新規投稿**（再投稿）。Web/Drafts は `dispatchNow()` |

**主要ファイル:**

| ファイル | 説明 |
|----------|------|
| `TodayDueTasksSlackService` | 本日期限タスク取得・ハッシュ比較・Slack 投稿/再投稿 |
| `PostTodayDueTasksCommand` | `slack:post-today-tasks`（cron から 9 時実行） |
| `SyncTodayDueTasksSlackJob` | 変更時の同期 Job |
| `TodayDueTasksSlackDispatcher` | `dispatch()` / `dispatchNow()` |
| `routes/console.php` | `Schedule::command('slack:post-today-tasks')->dailyAt(...)->timezone(JST)` |

**環境変数（`src/.env.example`）:**

```env
SLACK_CHANNEL_KYOU=
SLACK_CHANNEL_NAME_KYOU=Kyou
SLACK_KYOU_POST_HOUR=9
```

**本番インフラ追記:**

- crontab: `* * * * * cd ~/gemini-hub && docker compose exec -T app php artisan schedule:run`
- Bot ユーザー名: `ai`（`auth.test`）。表示名「AI」とは別

### デプロイ

本セッション前半は手動 SSH デプロイ。後半以降の `main` push は GitHub Actions 経由も利用可能（`AGENTS.md` 参照）。

### トラブルシュート（Kyou セッション）

| 問題 | 原因 | 対処 |
|------|------|------|
| Kyou に投稿されない | Bot 未参加 | `#Kyou` にアプリ追加（`/invite` は Bot 不可） |
| タスク登録成功だが返信なし | `#todo-work` 等に Bot 未参加 | カテゴリ `other` は投稿元チャンネルへ返信 → 各チャンネルに Bot 招待 |
| Kyou が更新されない | 通知 `not_in_channel` で Job 後半がスキップ（旧順序） | Kyou 先実行 + notify try/catch（`fef3320`） |
| 変更したのに Kyou が変わらないように見える | `chat.update` は `(edited)` のみで目立たない | 再投稿方式に変更（`1146938`） |
| 古い queue worker が残存 | ホスト上に Jun07 起動の `queue:work` が複数 | `systemctl restart laravel-queue` + 余剰プロセス整理 |

### 動作確認済み

- 本番 `#Kyou` へ手動投稿・再投稿（本日期限 3 件: 歯医者 / ハンバーガー / 今日のタスク）
- Slack から `#Kyou` に「今日のタスク」登録 → Kyou 同期 + 登録通知
